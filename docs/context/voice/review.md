# A review

## What the reader does next

The author of the pull request reads the review and fixes what it names, one finding at a time. The reviewer who posts it reads it first, and decides whether the request is ready. The author wants each finding at a file and a line. The reviewer wants the decision at the end.

## The rule

Give each finding with the file, the line, the convention it breaks, where that convention is written, and what to change. End with the decision, because that is the line the reviewer acts on. The test is that the author can fix every finding without asking what was meant. The steps of a review are in `docs/context/workflow/review-pr.md`. The checklist a review grades against is `docs/context/workflow/review-checklist.md`.

## One example from Site Kit

The owner puts one text here that a person corrected, from Site Kit's own issues, pull requests or reviews. It has three parts, each on its own line. The request, in one line. The text, as it read after the correction. One sentence on why it is right.

## Where the example came from

The issue, the pull request or the review the text came from, by its number.
