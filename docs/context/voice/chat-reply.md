# A chat reply

## What the reader does next

The person who asked reads the reply and acts on it. They run the command it gives, open the file it names, or answer the question it puts back to them. Nothing about how the answer was found helps them do any of that.

## The rule

Give the answer, and leave out the search behind it. The files opened, the count of what was found and the options set aside all stay out. The test is that every sentence tells the reader something they act on. After a playbook under `docs/context/workflow/`, report what that playbook says to report, such as a decision the reader can overrule, and no more.

## One example from Site Kit

The owner puts one text here that a person corrected, from Site Kit's own issues, pull requests or reviews. It has three parts, each on its own line. The request, in one line. The text, as it read after the correction. One sentence on why it is right.

## Where the example came from

The issue, the pull request or the review the text came from, by its number.
